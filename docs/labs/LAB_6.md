# Лабораторная работа 6 — Docker и Docker Compose

Автор: Достанова Жанелла, группа ИС/24А.

Проект: AutoRent, информационная система аренды автомобилей.

## Цель и реализация

Два образа описаны в Dockerfile и Dockerfile.frontend. Используется Python 3.12-slim, затем фиксированные зависимости requirements-lock.txt и исходный код. Compose связывает backend и frontend, публикует порты только на 127.0.0.1 и хранит SQLite в named volume rental_data. Healthcheck проверяет backend до старта frontend.

## Текущий статус

**Конфигурация docker compose config проверена успешно. Сборка и запуск контейнеров пока не подтверждены.** Docker Desktop на компьютере не запустился с ошибкой отсутствующего исполняемого файла. Наличие файлов Docker не является доказательством выполнения всей работы; следующий сценарий необходимо пройти после восстановления Docker Desktop.

## Проверка после запуска Docker Desktop

Из корня проекта:

```bash
docker info
docker compose config
docker compose up --build
```

Перед этим остановите локальные FastAPI и Streamlit, если они занимают порты 8000 и 8501. Дождитесь успешной сборки и готовности сервисов.

1. Откройте http://localhost:8000/docs и выполните GET /cars. Ожидается 200.
2. Откройте http://localhost:8501. Таблица должна загружаться через контейнер backend.
3. Создайте отдельную категорию и запишите её ID.
4. Остановите Compose клавишами Ctrl+C и выполните команды:

```bash
docker compose down
docker compose up
```

5. Повторите GET категории: запись должна сохраниться в томе. Не добавляйте -v к down: он удаляет данные тома.
6. Для диагностики используйте docker compose ps и docker compose logs backend frontend.

## Что объяснить в конфигурации

DATABASE_URL=sqlite:////data/database.db указывает на файл внутри примонтированного тома. BACKEND_URL=http://backend:8000 использует DNS-имя сервиса в сети Compose. Путь localhost внутри frontend означал бы сам frontend, а не backend.

.dockerignore исключает локальные базы, окружения, секреты и кеш. Установка зависимостей до COPY исходников позволяет повторно использовать слой с библиотеками при изменении кода.

## Ответы для защиты

**Контейнер и виртуальная машина?** Контейнер изолирует процессы и разделяет ядро хоста; виртуальная машина содержит отдельную гостевую ОС.

**EXPOSE, WORKDIR, COPY, CMD?** Документируют порт, выбирают рабочую папку, копируют файлы и задают команду старта. EXPOSE сам по себе не публикует порт.

**RUN и CMD?** RUN выполняется при сборке; CMD — при запуске контейнера.

**Зачем .dockerignore?** Уменьшает контекст сборки и исключает файлы, которые не должны попасть в образ. Локальное venv может быть несовместимо с ОС контейнера.

**Кто разрешает backend в IP?** Встроенный DNS Docker в сети Compose.

**Как сохранить SQLite?** В отдельном named volume. Файл только в writable layer исчезнет при удалении контейнера.
