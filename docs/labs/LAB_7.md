Автор: Достанова Жанелла, группа ИС/24А.

Проект: AutoRent, информационная система аренды автомобилей.

## Цель и реализация

В tests/test_api.py написаны интеграционные проверки FastAPI через TestClient. Для каждого теста создаётся отдельная временная SQLite-база, включаются внешние ключи и подменяется get_session. Инициализация основной базы в lifespan отключается на время теста. После проверки соединения закрываются и подмена удаляется.

## Запуск

Из корня проекта с активированным окружением:

```bash
python -m pytest -v
python verify.py
```

Uvicorn для TestClient запускать не требуется.

## Какие сценарии проверяются

| Проверка | Ожидаемый результат |
|---|---|
| GET списка, создание связанных сущностей | 200 и корректные записи |
| Поиск автомобиля и диапазон тарифа | Только подходящие строки |
| Строка, похожая на SQL-инъекцию, и символ % | Не расширяют выборку |
| PATCH одного поля | Остальные поля сохраняются |
| DELETE используемой категории | 409 |
| GET/PATCH после удаления | 404 |
| Пустое название, нулевой и отрицательный тариф | 422 |
| Повторное уникальное название | 409 |
| Явный null и отсутствующий внешний ключ | 422 |
| Неправильный диапазон цен | 422 |
| Пересекающаяся аренда автомобиля | 409 |
| Дата окончания раньше начала | 422 |
| Изменение тарифа категории | Исторический тариф аренды сохраняется |
| Следующая аренда с даты возврата | 201 |

Параметризация трёх случаев в test_validation вместе с остальными функциями даёт **6 тестов**. При выполненной проверке все шесть прошли. Предупреждение библиотеки о будущем изменении HTTPX не является провалом теста. verify.py также успешно проверил связи, ограничения, расчёт стоимости и повторный seed.

## Проверка кода и исправления

Ввод ограничен схемами, лишние поля запрещены; исключения уникальности/связей возвращают 409 без SQL-текста; удаление используемых справочников блокируется; PATCH повторно валидирует полную запись; пересечения аренды проверяются внутри сериализованной SQLite-транзакции. Это учебное локальное приложение без авторизации, не публичный сервис.

## Ответы для защиты

**Зачем автоматические тесты?** Они быстро повторяют сценарии после изменения кода и находят регрессии, которые легко пропустить вручную.

**Что такое TestClient?** Клиент для обращения к ASGI-приложению в тестовом процессе без отдельного uvicorn.

**Роль HTTPX?** Предоставляет HTTP-клиент, который используется TestClient для тестовых запросов.

**Польза ИИ при ревью?** Помогает искать пропущенные случаи и предлагать проверки. Его выводы нужно проверять запуском и анализом кода.

**Регрессионное тестирование?** Повторная проверка ранее работающих функций после изменения системы.
