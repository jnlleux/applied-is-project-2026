## Подготовка

Из корня проекта, Python 3.12 или новее:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python seed.py
python -m uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000/docs. Нажмите нужный маршрут, затем **Try it out**, заполните поля и нажмите **Execute**. В разделе **Server response** отображается реальный статус и JSON. Блок **Responses** ниже описывает возможные ответы, а не результат выполненного запроса.

Повторный seed не перезаписывает непустую базу. ID записей берите из текущего GET-ответа: они могут отличаться от примеров.

## Цель и реализация

Streamlit показывает четыре раздела: автомобили, категории, клиенты и аренда. Таблицы загружаются через HTTP API, а формы отправляют POST/PATCH/DELETE. Прямого доступа интерфейса к SQLite нет. Доступны поиск, фильтры, выбор связанных сущностей и подсчёт общей стоимости аренды.

## Запуск и демонстрация

Сначала запустите API по инструкции выше. В другом терминале из корня проекта:

```bash
source .venv/bin/activate
python -m streamlit run app/frontend/ui.py
```

Откройте http://localhost:8501.

1. Выберите «Автомобили». Таблица должна показать данные, полученные от API.
2. Введите Toyota в поиск. В таблице остаётся подходящий автомобиль.
3. Выберите «Категории», действие «Добавить». Введите название «Проверка интерфейса» и тариф 18000. Нажмите «Выполнить». Появится сообщение об успехе и строка в таблице.
4. Выберите «Изменить», нужную запись и новый тариф 21000. После сохранения таблица обновится.
5. Попробуйте создать категорию с уже существующим названием: UI покажет ошибку 409, полученную от сервера.
6. Выберите «Удалить», созданную категорию, отметьте подтверждение и выполните действие. Запись исчезнет.
7. Откройте Swagger и GET /categories: результат должен совпадать с интерфейсом.
8. При необходимости проверьте отказ: остановите только API клавишами Ctrl+C и обновите UI. Должно появиться сообщение о недоступном сервере. Затем снова запустите API.

## Как данные проходят систему

Поля формы → Python-словарь → requests с JSON → FastAPI → проверка схемы → сессия SQLModel → SQLite → HTTP-ответ → st.success или st.error → st.rerun.

В app/frontend/ui.py функция api задаёт timeout=10, обрабатывает ошибки HTTP и соединения. BACKEND_URL выбирает адрес сервера, по умолчанию http://127.0.0.1:8000. frontend/app.py сохраняет старую команду запуска и открывает новый интерфейс.

## Ответы для защиты

**Как связаны Streamlit и FastAPI?** HTTP-запросами и JSON. Это отдельные процессы; интерфейс вызывает API по адресу BACKEND_URL.

**params и json?** params передаёт строку запроса URL, json — тело запроса. Поиск использует params, создание — json.

**Что если сервер упадёт?** requests выбросит исключение соединения или таймаута. Оно перехватывается, пользователь получает понятное сообщение.

**Почему скрипт выполняется снова?** Это модель обновления Streamlit. Формы группируют ввод, session_state сохраняет уведомления между запусками.

**Плюсы и ограничения?** Быстрая разработка интерфейса на Python, но меньше свободы в дизайне и поведении, чем у самостоятельного HTML/CSS/JavaScript приложения.
