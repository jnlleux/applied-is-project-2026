## Подготовка

Из корня проекта, Python 3.12 или новее:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python seed.py
python -m uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000/docs. Нажмите нужный маршрут, затем **Try it out**, заполните поля и нажмите **Execute**. В разделе **Server response** отображается реальный статус и JSON. Блок **Responses** ниже описывает возможные ответы, а не результат выполненного запроса.

Повторный seed не перезаписывает непустую базу. ID записей берите из текущего GET-ответа: они могут отличаться от примеров.

## Цель и реализация

Добавлены PATCH, DELETE, поиск search и фильтры min_price/max_price. PATCH использует exclude_unset=True, объединяет переданные поля с текущей записью и повторно проверяет полную схему. Поэтому непереданное поле сохраняется, а явно переданный null для обязательного поля отклоняется.

Поиск использует параметризованные выражения SQLModel. Для автомобилей фильтр тарифа применяется к связанной категории. Удаление справочника, используемого другой записью, возвращает 409.

## Последовательная проверка

1. Создайте отдельную категорию POST /categories:

```json
{"name":"Лабораторная 4","daily_rate":16000}
```

Ожидается **201**. Далее везде используйте её реальный id.

2. PATCH /categories/{item_id}:

```json
{"daily_rate":19000}
```

Ожидается **200**, тариф 19000, прежние name и id. GET по ID подтверждает сохранение в базе.

3. GET /categories с search=Лабораторная 4, min_price=18000, max_price=20000. Ожидается **200**, созданная категория присутствует. Измените min_price на 20000 и max_price на 30000: она должна исчезнуть из результата.
4. Укажите min_price=30000 и max_price=10000. Ожидается **422**, минимум больше максимума.
5. PATCH той же категории:

```json
{"name":null}
```

Ожидается **422**, прежнее название остаётся.

6. DELETE /categories/{item_id}. Ожидается **204** без тела ответа.
7. GET и PATCH того же ID после удаления возвращают **404**.
8. Попробуйте удалить категорию, на которую ссылается автомобиль из seed. Ожидается **409**, связанные записи защищены.

## Дополнительная бизнес-логика аренды

Создание или изменение аренды проверяет существование клиента и автомобиля, положительный тариф и end_date > start_date. Для одной машины запрещены пересекающиеся интервалы аренды: ответ 409. Интервалы полуоткрытые, поэтому новая аренда в день окончания предыдущей допустима. Тариф копируется в договор: изменение категории не переписывает историю аренды. BEGIN IMMEDIATE в SQLite сериализует операции записи перед проверкой пересечения.

## Ответы для защиты

**PUT и PATCH?** PUT обычно заменяет ресурс целиком; PATCH изменяет отдельные поля и уменьшает объём передаваемых данных.

**Query-параметры?** Часть URL после ?: /categories?search=Комфорт&min_price=10000.

**Как защититься от None?** exclude_unset отличает непереданное поле, но не запрещает явный null. Полная повторная валидация запрещает его для обязательных полей.

**Зачем искать ID перед удалением?** Чтобы вернуть 404 при отсутствии и проверить зависимости перед изменением базы.

**CRUD?** Create — POST, Read — GET, Update — PATCH/PUT, Delete — DELETE.
